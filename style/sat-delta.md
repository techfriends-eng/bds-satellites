# Отличия статей сайтов-спутников от статей блога bigdataschool.ru

Основа — Style Guide V10-Blog и визуализации B5 из `style/upstream/article-write.rules.md` (форк bds-article).
Ниже только то, что у спутников иначе. Всё, что здесь не названо, действует как в блоге.

## Жанр и каркас

Статья спутника строится на чужом материале (статья, пост, релиз), но шире его. Каркас:

1. Лид-абзац `<p>` с главным ключом в первом предложении: какую задачу инженера решаем.
2. `<h2>` разбора исходника: о чём он, главное своими словами, ссылка на оригинал в теле.
3. Свой материал, один-два `<h2>` с `<h3>`: механизм под капотом, документация, ограничения,
   схема Mermaid по B5.1. Таблица сравнения с альтернативами обязательна (п. 8).
4. `<h2>` практики: стенд, код целиком, реальный вывод рядом с кодом (п. 9).
5. `<h2>` заданий: 2–3 задачи, решение каждой — `<details><summary>Решение</summary>…</details>`,
   код решений тоже прогоняется.
6. CTA: один абзац со ссылкой на самый близкий курс сайта (ссылка из списка курсов, со слэшем).
7. `<h2>Референсные ссылки</h2>` — 3–5 источников, оригинал обязателен.

Объём 1500–2500 слов без кода и таблиц.

## Чего у спутников нет

- Баннеров `[cbanner]` и `[github_banner]`: на сайтах-спутниках шорткодов нет (решение автора, ADR 0001).
  Вместо баннера — текстовая ссылка на курс (каркас, п. 6) и ещё одна по ходу текста, где уместно.
- Ссылок на bigdataschool.ru и на Wiki: статья живёт на своём домене.
- Telegram-анонса, брифа, квоты месяца, строк «Статус» и «Дата сдачи».

## Код и стенд

- Блок кода — `<pre class="EnlighterJSRAW" data-enlighter-language="ЯЗЫК">`, без других атрибутов.
  Код внутри HTML-экранирован: `&lt;`, `&gt;`, `&amp;`.
- Первая строка каждого файла — комментарий: имя файла, затем версии через « · ». У `run.sh` с
  `#!/usr/bin/env bash` этот комментарий — вторая строка.
  Пример: `# producer.py · confluent-kafka 2.6.1 · Kafka 4.3.2`, для YAML `# compose.yaml · …`,
  для `requirements.txt` — `# requirements.txt`. По имени из этой строки файл кладётся на стенд.
- Стенд — один `compose.yaml`: образы с точными тегами (образы кэша стенда в приоритете), `mem_limit` у
  каждого сервиса, всего до 6 ГБ, порты только на `127.0.0.1`. Kafka — только KRaft.
- `run.sh` (`set -euo pipefail`) поднимает стенд, ставит зависимости в `.venv` и запускает основной
  пример. Он не гасит стенд и не запускает решения заданий: раннер сам запускает каждый файл, у
  которого в статье есть место для вывода, и в конце делает `docker compose down -v`.
- Место для вывода — блок `generic`, в котором одна строка `[[output ИМЯ_ФАЙЛА]]`. Он стоит сразу после
  кода, вывод которого показывает. Вывод не выдумывается: его вставит раннер.
