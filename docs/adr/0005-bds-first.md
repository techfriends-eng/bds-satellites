# ADR 0005. Лучшее со спутниковых лент сначала предлагается bigdataschool.ru

- Статус: принято (2026-11-23, автор)
- Дата: 2026-11-23
- Дополняет: ADR 0001 (сверка со Stack Radar), `bds-sat-kafka/docs/plan-satellites.md` («отсеянное основным
  контуром спутник может брать»)

## Контекст

- bigdataschool.ru получает материал только из Stack Radar: новости (≈40–50 в месяц: 09 — 17, 10 — 50, 11 — 39
  по `news.articles`) и лонгриды bds-article с прогоном кода (6 в месяц, вход — одобренная новость Stack Radar).
  Хабр в карточках ограничен `PICK_HABR_SHARE` — было 0.4.
- Спутник уступает BDS только то, что Stack Radar уже предложил или одобрил (`dedup/radar.ts`). Собственные
  ленты спутников — YouTube (видео смотрит модель этапа video, v0.1.55), блоги вендоров, Medium — BDS не видит.
  Лучший материал по Kafka, Spark, ML, Airflow уходит спутникам, BDS живёт на пересказах Хабра.
- Автор 23.11: главное — самые интересные материалы, и первыми их получает BDS в виде полноценной статьи с кодом
  на прогоне; Хабр на BDS — кардинально меньше.

## Решение

1. **Предложение BDS.** После отбора (`select/rank.ts`) кандидат с `score_relevance >= select.bdsMinRelevance`
   (по умолчанию 8, до 0.1.59 было 9) и `score_depth >= select.bdsMinDepth` (по умолчанию 6, было 7) не идёт в черновик спутника, а
   получает статус `bds_offer` и строку в `sat.bds_offers` (site, candidate_id, url, title, summary, оценки и
   причина, kind источника, offered_at, status `pending|approved|rejected|expired`, decided_at). URL уникален:
   два спутника с одним материалом дают одно предложение.
2. **Карточка с кнопками в Telegram.** Stack Radar читает `pending` из `sat.bds_offers` отдельным треком
   `longread` в своей теме служебного чата. Кнопки: «✅ Лонгрид BDS» и «↪ Отдать спутнику»; реплай не нужен.
   Карточка на русском, как у новостей (`localizeCandidate`), с пометкой «видео» для YouTube.
3. **Решение и срок.** «Лонгрид BDS» → `approved`: материал — вход bds-article (ссылка из карточки), спутник
   ставит кандидату `radar` и больше его не берёт. «Отдать спутнику» → `rejected`, без ответа 7 суток →
   `expired`; в обоих случаях спутник возвращает кандидата в `new` и берёт по обычному отбору.
4. **Хабр.** `PICK_HABR_SHARE` по умолчанию 0.15 (stack-radar PR #20).
5. **Темы BDS без спутника** (Airflow и другие направления курсов bigdataschool.ru): сбор спутникового
   конвейера с конфигом `bds`, режим «только предложения» — сбор, предотбор, отбор, `sat.bds_offers`, без
   черновиков и WP. Каналы и ленты — отдельная задача «каналы BDS по направлениям курсов».
   Сделано в 0.1.59: `mode: offers`, каналы в `docs/bds-channels.md`.
   Хост — auto08, не progon (решение автора 2026-11-27): стенда и Docker у режима нет, а progon включается
   по требованию ради прогона кода статей. Репо `techfriends-eng/bds-offers`, пакет с 0.1.60 (без brand и
   Docker). Отклонение от ADR 0001 §3 «эксплуатация на progon» — только для этого конфига.

## Реализация

- bds-satellites 0.1.56: миграция `sat.bds_offers` (роль `sat_writer` — insert/select, роль Stack Radar —
  select/update по status и decided_at), статус кандидата `bds_offer`, шаг сверки решений в начале прогона,
  ключи `select.bdsMinRelevance`/`bdsMinDepth`, CHANGELOG, RUNBOOK §5, templates/site.
- stack-radar: трек `longread` (тема «longreadBDS» служебного чата -1004445665712, `PICK_LONGREAD_THREAD_ID=1942`, срок `PICK_LONGREAD_EXPIRE_HOURS` = 168),
  кнопки и обработка callback, RUNBOOK §8–9.
- Порядок выката: Stack Radar с треком (пустая таблица — карточек нет) → bds-satellites 0.1.56 на сайты.

## Последствия

- Спутник получает лучший материал на 7 дней позже или не получает. Это осознанно: приоритет BDS.
- Поток карточек растёт: на 6 лонгридов в месяц нужно больше предложений, чем BDS возьмёт. Порог 9/7
  подбирается по первым двум неделям (сколько карточек и сколько одобрено). 2026-11-27 автор снизил до 8/6:
  при 9/7 за 23–27.11 было 4 предложения, а BDS — главный сайт.
- Видео как вход bds-article: стадия 1 плагина работает от ссылки; текст видео лежит у спутника в
  `drafts/.video/<id>.md` — передача в bds-article отдельной задачей, если понадобится.
