# ADR 0002. Модели по этапам и векторная документация продуктов на своей инфраструктуре

- Статус: предложено
- Дата: 2026-11-02

## Контекст

Первые прогоны трёх сайтов (2026-11-01) стоили $2.5–2.8 за прогон при лимите ключа OpenRouter $10 в месяц на
сайт. По `llm_calls` расход распределился так: правка (revise) — 43 %, написание (write) — 25 %,
смысловая проверка — 17 %, превью — 9 %. Почти всё уходит на вывод Sonnet 5.5 ($10 за 1M токенов). Часть
правок вызвали баги проверок, они исправлены в v0.1.13–v0.1.16.

Требования автора (2026-11-02):
- Импортозамещение: обкатывать модели, которые работают с русским текстом, и по возможности использовать
  свою инфраструктуру. В первую очередь Qwen через Ollama.
- Подписка Claude (лимит на неделю, сброс в четверг 04:00 МСК) используется по остаткам, работа
  распределяется равномерно, а не одним прогоном по расписанию.
- Документация продуктов хранится в своей векторной базе. Сначала три проекта: kafka, spark,
  python (ML). Для каждого продукта берётся одна версия, на которой стоит стенд, а не все версии.

Что есть сейчас:
- supan8n (Yandex Cloud, работает постоянно): 4 vCPU Icelake с AVX-512, 15 ГБ RAM, 19 ГБ свободного
  диска.
  - Ollama 0.32.9 с `nomic-embed-text`.
  - pgvector 0.8.2, схема `rag`: 2171 документ блога, wiki и курсов, 21 144 фрагмента, вектор 768,
    `tsv`.
  - Индексатор `/opt/rag/indexer.py` по таймеру `bds-rag-index.timer`, поиск через `mcp-pg`
    (`/opt/mcp/pg/server.py`).
  - **`/opt/rag` и `/opt/mcp` не лежат в git.**
- Замеры на supan8n (2026-11-02):

  | Модель | Чтение промпта | Генерация / эмбеддинг |
  |---|---|---|
  | `qwen3:8b` | 7.5 ток/с | 1.3 ток/с; русский текст грамотный |
  | `qwen3-embedding:0.6b` | ~290 ток/с | вектор 1024, многоязычный |

  Черновик статьи на supan8n (~25k токенов промпта, ~8k вывода) займёт 2.5–3 часа при полной загрузке
  сервера. На этом же сервере работают хаб и Supabase.
- Подписка Claude: `claude -p --output-format stream-json` выдаёт `rate_limit_event` с загрузкой
  окон `five_hour` и `seven_day` и временем их сброса.

## Решение

### 1. Документация: схема `docs` на supan8n

| Сайт | Продукт | Версия |
|---|---|---|
| kafka | Apache Kafka (Connect, Streams) | 4.3.2 |
| kafka | Debezium, Apicurio Registry | последние, совместимые с Kafka 4.3 (сверяются при сборке манифеста) |
| spark | Apache Spark | 4.0.4 и 4.2.1 |
| spark | Delta Lake, Apache Iceberg | совместимые со Spark 4.0 и 4.2 |
| spark | Apache Flink | 2.3.0 |
| python | Ollama | 0.40.13 (как образ стенда) |
| python | LangChain 1.4.7, LangGraph 1.2.19, MLflow 3.17.2, scikit-learn 1.9.1, pandas 3.1.0, Polars 2.1.0, DuckDB 2.0.0, GigaChat SDK 0.2.3 | |

- Источник — официальные docs-репо на GitHub по тегу релиза: `git clone --depth 1 --branch <тег>
  --sparse`, только каталоги документации. Список продуктов и версий хранится в манифесте `docs.yaml`.
- Нарезка по заголовкам (markdown, asciidoc, rst), как в `rag.chunks`: `heading_path`, `context`,
  `tsv`. Продукт и версия записываются в отдельные колонки.
- Эмбеддер — `qwen3-embedding:0.6b` (1024), многоязычный: запрос на русском находит английский текст.
  Схема отдельная от `rag`, потому что размерность другая. Блог остаётся на `nomic-embed-text`, его
  переиндексация решается отдельно.
- Таблицы: `docs.sources` (продукт, версия, репо, тег), `docs.files` (путь, sha256),
  `docs.chunks` (vector(1024), tsv, heading_path, product, version).
- Индексация идёт ночью с `nice` и ограничением потоков. Повторно индексируются только файлы с
  изменившимся sha256. Первичный объём по списку — несколько млн токенов, это часы.
- Кто читает:
  - конвейер спутников: план и статья получают фрагменты нужной версии вместо обхода сайтов, а
    смысловая проверка сверяет по ним флаги и API;
  - `mcp-pg`: новый инструмент `docs_search` для статей блога и wiki.
- Код — на TS (ADR 0002 handbook) в новом репо `techfriends-eng/bds-docs-index`, развёртывание в
  `/opt/bds-docs-index` на supan8n, запуск в Docker (Node на хосте нет).

### 2. Модели по этапам

| Этап | Основная модель | Запасная |
|---|---|---|
| select | Haiku 5.5 (OpenRouter) | — |
| plan, write, fix | облачная открытая модель (DeepSeek V4 Flash или Qwen через OpenRouter); по итогам A/B | Sonnet 5.5 (OpenRouter) |
| review, revise | Sonnet 5.5 через подписку Claude (`claude -p`), по остаткам лимита | Sonnet 5.5 (OpenRouter) |
| превью | `gemini-2.5-flash-image` | `gemini-3-pro-image-preview` |

- Генерация на supan8n не используется (замеры выше). Свой сервер под Qwen (CPU 16 vCPU / 64 ГБ или
  GPU) — отдельное решение автора. Тогда в A/B добавляется Qwen на своём сервере, и он становится
  основной моделью для plan, write и fix.
- В конфиге сайта у этапа — список моделей с откатом, а модель может быть `openrouter:<id>`,
  `claude-cli:<alias>` или `ollama:<host>/<tag>`.
- Подписка: перед вызовом `claude-cli` читается `rate_limit_event`. Вызов идёт, если окно 5 часов
  занято меньше чем на порог (по умолчанию 30 %, чтобы осталось на работу автора) и недельное окно не
  опережает равномерный темп до сброса. В последние 24 часа перед сбросом порог поднимается. Нет
  события или порог превышен — вызов уходит на запасную модель.
- Правка присылает пары замен «было → стало», а не всю статью.

### 3. Равномерная работа

Таймер сайта срабатывает несколько раз в сутки, а не раз в неделю. За один запуск — не больше одного
шага на тему (план, статья, стенд, проверки или правка). Новые темы выбираются в день сайта, остальные
шаги идут, пока есть лимит. progon включается расписанием EventBridge в эти окна. Сторож простоя
гасит его, как и сейчас.

## Последствия

- Расход OpenRouter: с ~$2.5 до ~$0.2–0.4 за прогон, в основном запасные вызовы и превью.
- Конвейер зависит от supan8n (поиск по документации). Если supan8n недоступен, план и статья
  пишутся без фрагментов документации, как сейчас.
- progon не в tailnet, а supan8n принимает только ssh, http/https и Tailscale. Для поиска progon
  входит в tailnet. Это настраивает автор, классификатор не даёт мне менять сеть.
- `/opt/rag` и `/opt/mcp` переносятся в git отдельной задачей (стандарт handbook): репо `bds-rag`,
  без изменения поведения.
- `qwen3:8b` удаляется с supan8n: для конвейера она не нужна, а 5 ГБ диска пригодятся под клоны
  документации.

## Отвергнуто

- Генерация на supan8n: 1.3 ток/с, часы на статью, а сервер общий с хабом.
- Все версии продукта в индексе: шум в поиске и лишний объём. Берём версии стенда.
- Бесплатные модели OpenRouter (`:free`): DeepSeek и Kimi среди них нет, есть очередь и лимит запросов
  в день, провайдер может хранить промпты.
- Переиндексация `rag` на новый эмбеддер в этом ADR: другой объём работ, решается отдельно.
