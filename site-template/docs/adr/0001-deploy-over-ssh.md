# ADR 0001. Деплой на progon по ssh с wsa100, а не через ops_run

- Статус: принято
- Дата: __DATE__

## Контекст

Стандарт 07 handbook: деплой — одно действие `ops_run deploy-<app>` через MCP-шлюз хоста. На progon
MCP-шлюза нет: сервер включается по требованию (`stand_progon.sh up` или EventBridge) и выключается
сторожем простоя. Отдельный шлюз ради деплоя раз в несколько недель держал бы сервер включённым.

## Решение

Деплой — `node_modules/bds-satellites/ops/deploy-site.sh` в клоне `/opt/bds-sat-__SITE__` от пользователя сайта,
вызов по ssh с wsa100 (RUNBOOK §6). Шаги те же, что у `ops_run`: чистое дерево, ff-only, npm install,
selfcheck, smoke.

## Почему

- MCP-шлюз на progon — отброшено: постоянный процесс на сервере, который включается раз в неделю.
- Деплой через auto08 — отброшено: auto08 не ходит на progon по ssh и не должен.

## Последствия

Деплой требует включённого progon. Результат деплоя виден в выводе ssh и в журнале хаба (smoke пишет `sat.runs`).
